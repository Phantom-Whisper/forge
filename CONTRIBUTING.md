# Contributing


## Development Setup
1. Clone the repository.
2. Install required framework & dependencies.
3. Run the app.

## Branching Strategy

- ***main*** production-ready code.
- ***develop*** integration branch.
- ***feature/**** or ***feat/**** new features.
- ***fix/**** fix bugs.
- etc...

## Commit Convention
We follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) to maintain a consistent and readable commit history.

- ***feat*** branches introduces a new feature or functionality.
  **example:**  `feat: add transaction history`
- ***fix*** branches fixes a bug or incorrect behavior.
  **example:**  `fix: correct balance calculation`
- ***doc*** branches adds or updates project documentation.
  **example:**  `doc: update readme`
- ***refactor*** branches restructures existing code without changing its external behavior.
  **example:** `refactor: simplify transaction processing`
- ***style*** branches makes code style changes without affecting functionality.
  **example:** `style: format account repository`
- ***perf*** branches improves application performance.
  **example:** `perf: optimize transaction queries`
- ***build*** branches changes build systems, dependencies or build configuration.
  **example:** `build: update kotlin dependencies`
- ***ci***: branches changes CI/CD configuration and workflows.
  **example:** `ci: configure automated tests`
- ***chore*** branches performs maintenance tasks that don't fit into other categories.
  **example:** `chore: update gitignore`
